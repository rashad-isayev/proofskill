# Contributing to ProofSkill

Bug fixes, tests, documentation, and focused improvements are welcome. Use GitHub to fork the repository and open a pull request against `main`. Describe the problem, what changed, and how you verified it. GitHub runs the required CI checks on the pull request.

Start with the [architecture guide](architecture.md) for a map of the assessment workflow. For local setup and test commands, see the [README](README.md#optional-isolated-local-development). Obtain the repository owner's permission before running or adapting a copy outside GitHub's service.

Use fictional data in tests, screenshots, and examples. Keep credentials, candidate information, real invitation links, and recordings out of commits and pull requests. Report security vulnerabilities privately using the instructions in [SECURITY.md](SECURITY.md#reporting-a-vulnerability).

## Permission to include your contribution

You keep any ownership rights you hold in your contribution. By submitting a pull request, you grant the ProofSkill repository owner non-exclusive, royalty-free permission to use, modify, and publish your contribution as part of ProofSkill. Confirm in the pull request that you have the right to grant this permission. Identify any third-party material and its license before submission. The maintainer checks that confirmation before merging.

The repository's [copyright notice](README.md#copyright-and-contributions) describes permissions for the existing ProofSkill code.
